# HTTP и HTTPS

## HTTP

**HTTP (Hypertext Transfer Protocol)** - протокол, по которому клиент и сервер обмениваются данными в интернете

Пример:

```
Browser → HTTP Request → Server
Browser ← HTTP Response ← Server
```

HTTP работает поверх транспортного протокола, обычно **TCP**

Стандартный порт:

```
HTTP → TCP 80
```

---

## HTTP Request

**HTTP Request** - запрос, который клиент отправляет серверу

Пример:

```
GET /profile HTTP/1.1
Host: example.com
User-Agent: Firefox
```

Основные части:

* `GET` - HTTP-метод;
* `/profile` - путь к ресурсу;
* `HTTP/11` - версия HTTP;
* `Host`- домен сервера;
* `User-Agent` - информация о клиенте

### Основные HTTP-методы

| Метод    | Назначение                |
| -------- | ------------------------- |
| `GET`    | Получить данные           |
| `POST`   | Отправить данные          |
| `PUT`    | Полностью обновить ресурс |
| `PATCH`  | Частично изменить ресурс  |
| `DELETE` | Удалить ресурс            |

---

## HTTP Response

**HTTP Response** - ответ сервера на HTTP-запрос

Пример:

```
HTTP/11 200 OK
Content-Type: text/html
```

После заголовков сервер может отправить тело ответа:

```
<html>
    
</html>
```

### Основные HTTP Status Codes

| Код                         | Значение                   |
| --------------------------- | -------------------------- |
| `200 OK`                    | Запрос успешно выполнен    |
| `301`                       | Постоянное перенаправление |
| `302`                       | Временное перенаправление  |
| `400 Bad Request`           | Некорректный запрос        |
| `401 Unauthorized`          | Требуется аутентификация   |
| `403 Forbidden`             | Доступ запрещён            |
| `404 Not Found`             | Ресурс не найден           |
| `500 Internal Server Error` | Ошибка сервера             |

---

# HTTPS

**HTTPS (HTTP Secure)** - HTTP, работающий через защищённое TLS-соединение

Упрощённо:

```
HTTP + TLS = HTTPS
```

Стандартный порт:

```
HTTPS → TCP 443
```

Пример:

```
https://example.com
```

---

## TLS

**TLS (Transport Layer Security)** - криптографический протокол, который защищает соединение между клиентом и сервером

TLS обеспечивает:

### 1 Confidentiality - конфиденциальность

Данные шифруются, поэтому посторонний не должен иметь возможности просто прочитать содержимое трафика

### 2 Integrity - целостность

TLS помогает обнаружить изменение данных во время передачи

### 3 Authentication - аутентификация

TLS-сертификат позволяет браузеру проверить подлинность сервера и его связь с доменом

---

## TLS-сертификат

При HTTPS сервер предоставляет **TLS-сертификат**

Упрощённо:

```
example.com
     ↓
TLS Certificate
     ↓
Проверка браузером
     ↓
Защищённое соединение
```

Если сертификат недействителен или возникла проблема с его проверкой, браузер может показать предупреждение

---

# Различия HTTP и HTTPS

| HTTP                                       | HTTPS                                        |
| ------------------------------------------ | -------------------------------------------- |
| TCP 80                                     | TCP 443                                      |
| Нет TLS-шифрования                         | Использует TLS                               |
| Данные передаются без защиты TLS           | Данные защищены TLS                          |
| Не обеспечивает TLS-аутентификацию сервера | Использует TLS-сертификаты                   |
| Менее безопасен для чувствительных данных  | Используется для защищённой веб-коммуникации |

# HTTP и HTTPS в сети

Когда пользователь открывает:

```
https://example.com
```

упрощённая последовательность выглядит так:

```
Browser
   ↓
  DNS
   ↓
IP address
   ↓
TCP connection
   ↓
  TLS
   ↓
 HTTPS
   ↓
  GET /
   ↓
Web Server
   ↓
Application
   ↓
Database
```

С точки зрения сетевой модели:

```
Application: HTTP / HTTPS
Transport:   TCP
Network:     IP
Link:        Ethernet / Wi-Fi
```

# HTTPS и кибербезопасность

HTTPS защищает **соединение**, но не гарантирует отсутствие уязвимостей в самом веб-приложении

Например, сайт может использовать HTTPS и при этом иметь:

* XSS;
* SQL Injection;
* IDOR / Broken Access Control;
* CSRF;
* SSRF;
* уязвимости API;
* проблемы с аутентификацией и сессиями

Поэтому:

```
HTTPS ≠ безопасное веб-приложение
```

HTTPS защищает передачу данных между клиентом и сервером, а безопасность самого приложения зависит также от его архитектуры, кода, аутентификации, авторизации и обработки пользовательских данных

## Главное

> **HTTP** - протокол обмена данными между клиентом и сервером

> **HTTPS** - HTTP, защищённый с помощью TLS

> **HTTP → TCP 80**

> **HTTPS → TCP 443**

> **HTTPS защищает соединение, но не устраняет уязвимости самого веб-приложения**
