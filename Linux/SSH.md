# SSH — Secure Shell

**SSH (Secure Shell)** - протокол, который позволяет **безопасно подключаться к удалённому компьютеру через сеть и управлять им через терминал**

Например:

```
Ваш компьютер                 Удалённый сервер
      │                              │
      │────── SSH connection ───────>│
      │                              │
      │       команды / данные       │
      │<─────────────────────────────│
```

После подключения можно работать с удалённым компьютером почти так же, как с терминалом на своей машине

---

# Для чего используется SSH

SSH часто используется для:

* удалённого управления Linux-серверами;
* администрирования серверов;
* передачи файлов;
* выполнения команд на удалённой машине;
* безопасного доступа к сетевому оборудованию;
* автоматизации

Стандартный порт SSH — **22/TCP**

---

# Как подключиться

Основная команда:

```
ssh username@ip_address
```

Например:

```
ssh user@192.168.1.10
```

Здесь:

```
ssh             → SSH-клиент
user            → имя пользователя на удалённой машине
192.168.1.10    → IP-адрес удалённой машины
```

После подключения терминал будет работать уже на удалённом компьютере

Например:

```
local@computer:~$ ssh user@192.168.1.10

user@192.168.1.10's password:

user@server:~$
```

Обратите внимание, что после подключения приглашение терминала изменилось:
Было:

```
local@computer
```

Стало:

```
user@server
```

Это означает, что команды теперь выполняются **на удалённом сервере**

---

# SSH-клиент и SSH-сервер

Для работы SSH используются две стороны:

```
SSH Client                    SSH Server
    │                              │
    │────── connection ───────────>│
    │                              │
```

**SSH client** — программа на компьютере, с которого выполняется подключение

**SSH server** — программа на удалённой машине, которая принимает SSH-подключения

В Linux SSH-сервером обычно является **OpenSSH Server**

Проверить его состояние можно:

```
sudo systemctl status ssh
```

Запустить:

```
sudo systemctl start ssh
```

Остановить:

```
sudo systemctl stop ssh
```

Перезапустить:

```
sudo systemctl restart ssh
```

# Порт SSH

По умолчанию SSH использует:

```
TCP 22
```

Можно указать другой порт при подключении:

```
ssh -p 2222 user@192.168.1.10
```

Здесь:

```
-p 2222 → использовать порт 2222
```

# Аутентификация

SSH должен проверить, **имеет ли пользователь право подключиться к серверу**

Основные способы:

1. пароль;
2. SSH-ключи

Пример реального подключения:

```
ssh server@192.168.1.100

The authenticity of host '192.168.1.100 (192.168.1.100)' can't be established.
ED25519 key fingerprint is SHA256:x8+yZ9a...
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '192.168.1.100' (ED25519) to the list of known hosts.

server@192.168.1.100's password:
```
**То что хочу подметить, и это очень важно**

*При вводе пароля символы не отображаются (ни букв, ни звездочек, ни точек)   
Нужно просто вслепую ввести пароль и нажать Enter*

Допустим вы ввели нужный пароль:
```
Welcome to Ubuntu 22.04.3 LTS (GNU/Linux 5.15.0-88-generic x86_64)

 * Documentation:  https://help.ubuntu.com
 * Management:     https://landscape.canonical.com
 * Support:        https://ubuntu.com/advantage

Last login: Fri Dec 28 19:37:00 2026 from 192.168.1.50
server@ubuntu-server:~$ 
```

# SSH-ключи

SSH-ключи позволяют использовать криптографическую пару:

```
Private key       Public key
```

У пользователя есть:

**Private key** - закрытый ключ, который должен оставаться только у владельца

**Public key** - открытый ключ, который можно разместить на сервере

Упрощённо:

```
Ваш компьютер                    Сервер
     │                              │
Private key                    Public key
     │                              │
     └──── authentication ──────────┘
```

Приватный ключ **нельзя передавать другим людям**

---

# Создание SSH-ключа

На Linux можно создать ключ командой:

```
ssh-keygen
```

Обычно ключи сохраняются в:

```
~/.ssh/
```

Например:

```
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

Здесь:

```
id_ed25519
```

- приватный ключ

```
id_ed25519.pub
```

- публичный ключ

---

# Копирование публичного ключа

Для Linux-сервера можно использовать:

```
ssh-copy-id user@192.168.1.10
```

После этого публичный ключ пользователя будет добавлен на сервер

Обычно он хранится в:

```
~/.ssh/authorized_keys
```

---

# Подключение с помощью ключа

После настройки ключа можно подключаться:

```
ssh user@192.168.1.10
```

SSH использует ключ для аутентификации

Если приватный ключ находится не в стандартном месте, можно указать его:

```
ssh -i ~/.ssh/my_key user@192.168.1.10
```

---

# Выполнение команды без открытия интерактивной сессии

SSH позволяет выполнить одну команду на удалённом компьютере:

```
ssh user@192.168.1.10 "whoami"
```

Сервер выполнит:

```
whoami
```

и вернёт результат.

Например:

```
user
```

Можно выполнить и более сложную команду:

```
ssh user@192.168.1.10 "ip addr"
```

---

# Передача файлов

SSH также используется для безопасной передачи файлов

Для этого существует **SCP (Secure Copy Protocol)**

Отправить файл на сервер:

```
scp file.txt user@192.168.1.10:/home/user/
```

Скачать файл с сервера:

```
scp user@192.168.1.10:/home/user/file.txt ./
```

Также можно использовать **SFTP**, который работает поверх SSH.

---

# Проверка доступности SSH

Можно проверить, открыт ли SSH-порт:

```
nc -zv 192.168.1.10 22
```

или:

```
nmap -p 22 192.168.1.10
```

Если порт доступен, SSH-сервис может принимать подключения.

---

# SSH и безопасность

SSH шифрует соединение между клиентом и сервером

Это защищает передаваемые данные от простого перехвата в сети

Однако сам SSH-сервис всё равно необходимо правильно настраивать

Например, важно:

* использовать сильную аутентификацию;
* защищать приватные ключи;
* регулярно обновлять OpenSSH;
* ограничивать доступ к SSH;
* использовать firewall;
* отключать ненужные способы аутентификации;
* не выдавать пользователям больше прав, чем необходимо

# Главное, что нужно запомнить

```
SSH
│
├── Secure Shell
├── удалённое управление
├── TCP
├── стандартный порт 22
├── SSH Client
├── SSH Server
├── Password authentication
└── SSH Keys
      ├── Private key
      └── Public key
```

Главная идея:

> **SSH позволяет безопасно подключиться к удалённому компьютеру и управлять им через командную строку**
